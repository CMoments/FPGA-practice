VibeYoga-Hackathon-QEC event

这个活动要求参与者把自己现实中某个重复性的研究或开发工作流（如文献综述、代码库开发、论文写作等），打包成一个可复用、可自动化的“Harness 系统”。

这个系统包含智能体指令、命令行工具、MCP 服务、测试、Makefile 和文档。活动强调用 AI 编码工具（如 Claude Code）来“氛围式编程”并验证，最终分享成果，让其他人也能复用这套自动化流程。

步骤

Please use the reflect skill to critically evaluate my project idea.
Jin-Guo Liu: Prompt:

clone this repo to local machine: https://github.com/CodingThrust/problem-reductions/ , check it, see what can we learn from it?
Jin-Guo Liu: Reflect on the design file:

invoke this skill: https://github.com/CodingThrust/VibeTraining/blob/main/.claude/skills/reflect/SKILL.md on the design file.
Jin-Guo Liu: Best practise, make a test plan

Brainstorm: let us design a test plan together to validate the correctness of the software. Generate test datasets as json files that records input and expected output. These tests must cover all main APIs.
Jin-Guo Liu: https://luckyapi.chat/Jin-Guo Liu: Hint: give AI agents all permission
headless modeJin-Guo Liu: https://arxiv.org/abs/2604.11535

要求

一个GitHub repo，至少包括：

目标是让王鑫老师和我仅仅通过看README就一次性测试完所有feature，并相信你们做的是对的。不允许有任何解释和介绍。

Jin-Guo Liu: 可以假设用户/开发者有AGENT。
Jin-Guo Liu: 然后今天活动开始前，希望每组有一份工作的MVP，所有测试通过，提交到GitHub，并和团队成员同步产品形态。
Jin-Guo Liu: 否则会没法进入到下个阶段。
Jin-Guo Liu: 这样吧，也明确点，开始前：

每组确定一个组长，维护repo，给每个成员至少下达一个小任务，保证成员有能力通过agent提交一个GitHub pr贡献代码，并给组长验收合并。
在 README 申明想要开发的feature list。
Jin-Guo Liu: 开始前我会验收每组PR merge的情况，这是协作的基础，希望重视。

Jin-Guo Liu: Goal for today: CLAUDE.md + test plan + CI/CD

  • how to create badges in README for CI/CD?

  • design 3 logos for this project, let me pick

  • push the test coverage to >95%

  • for this project, what can we learn from https://github.com/Deltakit/deltakit ?

  • protect the main branch.

  • code review skill: https://github.com/CodingThrust/problem-reductions/blob/main/.claude/skills/review-quality/SKILL.md

  • brainstorm a test plan and file an issue.

  • implement issue x in a new pr.
